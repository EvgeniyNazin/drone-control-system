## Описание проекта

Демонстрация работы с классами, композицией и агрегацией на примере тактической системы управления боевыми квадрокоптерами.

В работе реализованы три связанных класса:

- **`Target`** (Цель) — объект, подлежащий уничтожению или разведке. Хранит статус (`eActive` / `eDestroyed`). Уничтожается вместе с миссией (**композиция**).
- **`Drone`** (Дрон) — автономный летательный аппарат с боекомплектом и батареей. Живёт независимо от миссии (**агрегация**).
- **`Mission`** (Миссия) — боевая задача, объединяющая дронов и цели. Владеет целями (создаёт и удаляет их), использует дронов по указателю.

## Что демонстрирует программа

1. **Композиция (Mission → Target)**
   Миссия создаёт цели через `new` в методе `AddTarget` и удаляет их через `delete` в деструкторе. При уничтожении миссии автоматически уничтожаются все её цели.

2. **Агрегация (Mission → Drone)**
   Дроны создаются вне миссии и передаются по указателю. При уничтожении миссии дроны продолжают существовать и могут быть использованы в других миссиях.

3. **Проверка правил предметной области**
   - Цель не может быть уничтожена дважды (повторный вызов `Destroy()` игнорируется).
   - Дрон без боекомплекта не может атаковать цель — действие отменяется с сообщением о нарушении.
   - Индексы цели и дрона при ударе проверяются на допустимость.

4. **Работа с памятью**
   - Статическая инициализация объектов (на стеке)
   - Динамическая инициализация через `new` / `delete`
   - Динамический массив объектов класса (`new Drone[2]`)
   - Массив указателей на объекты класса (`new Mission*[2]`)
   - Работа по ссылке и по указателю

5. **Соответствие code style**
   - Все поля `protected`, доступ через методы
   - Удалены все четыре специальных метода (copy/move constructor/assignment)
   - Инициализация полей через `{}` в объявлении
   - `[[nodiscard]]` на всех геттерах
   - `static constexpr auto TAG` и `BASE_NAME` в каждом классе
   - Алиас типа `using IdType = std::int32_t`
